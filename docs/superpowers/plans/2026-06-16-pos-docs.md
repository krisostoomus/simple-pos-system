**Goal:** Document the finished system: C4 + supporting Mermaid diagrams, a lean root README with quick-start, concise per-component READMEs, and a DEPLOY.md — all accurate to the implemented code, with no company/brand reference anywhere.

**Plan set:** Plan 4 of 4 (final). Prereq: Plans 1–3 merged. Spec §12. Docs only — no code changes.

**Key facts to document accurately:**
- Stack: Blazor WASM (nginx) → REST `/api/v1` + SignalR `/hubs/stock` → ASP.NET Core minimal API (.NET 10, lightweight Clean Architecture: Domain → Application → Infrastructure → Api) → PostgreSQL (EF Core 10, `xmin` optimistic concurrency).
- Ports via compose: **web** host `8080`→container `80`; **api** host `8081`→container `8080`; **db** internal only. Browse `http://localhost:8080`; Swagger at `http://localhost:8081/swagger`; health `http://localhost:8081/health`.
- CORS allowlists both `http://localhost:8080` and `http://127.0.0.1:8080` (the client calls the api at the host URL, so the browser origin must be allowlisted — use the same host spelling you browse with).
- Demo staff credential (compose dev values): username `staff`, password `staff-password`. JWT protects `PUT /products/{id}/stock` and `GET /reports/summary`.
- Bonus done: edible + second-hand catalog (with Estonian translations) seeded from `seed.json` on startup. Second-hand items start at 0 stock; staff set them on the day via the admin page.
- Money is integer cents throughout; change is computed greedily over euro denominations.
- Tests: Domain 27 + Application 21 + API integration 15 (Testcontainers Postgres) + Web bUnit 7 + E2E 3 (Reqnroll/Playwright).
